## Start-up sequence (read in this order)

1. `docs/goal.md` — primary goal, immutable constraints, anti-goals.
2. `docs/Philosophy.md`, `docs/Axioms.md`, `docs/Invariants.md` — what must not be violated.
3. `docs/ResearchLog.md` — read the last five entries.
4. `docs/Conflicts.md`, `docs/Decisions.md` — open conflicts and architecture decisions (ADR).
5. `docs/roadmap.md`, `docs/TaskQueue.md` — current phase and highest-priority unclaimed task.
6. `docs/AgentSync.md` — claim the task before starting work.
7. `docs/QA_Protocol.md` — how work must be verified and reported.

## Operating rules

- Documentation-first, code-second (`docs/AI_Protocol.md`).
- Only raw L2 tick data as input. No external parameters, filters, indicators, or risk management (`docs/goal.md`).
- Every change must preserve the invariants in `docs/Invariants.md`. Test thresholds are fixed and must not be loosened to make a test pass (`docs/QA_Protocol.md`, P3).
- No execution, no real money, no profit claims. This is a research project, not a trading system.
- Log state changes in `docs/ResearchLog.md`, conflicts in `docs/Conflicts.md`, and user-visible changes in `docs/Changelog.md`.

## Before stopping

Follow `docs/AgentHandoff.md`: update `docs/AgentSync.md`, commit with tests passing, update `docs/ResearchLog.md` and `docs/Changelog.md`, and leave no conflict unresolved.
